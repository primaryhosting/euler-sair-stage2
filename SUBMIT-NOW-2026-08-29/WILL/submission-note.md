# WILL — technique without the table

## What it does and why
WILL solves the same magma-implication task as EULER and emits the same judge-verifiable Lean certificates, but with the memorized mathematical content removed. It is both a competitive solver and a controlled ablation: how much does reusable search technique recover once the implication oracle, model bank, answer lookup, and pair-specific proofs are gone? Its value is generalization and interpretability. Manifesto and full write-up: https://riemannlab.com/will

## How it works
Everything is built from the two input equations at runtime.
- FALSE: exhausts all tables of orders 2–3; tries projection, constant, affine, bilinear and related families; then bounded backtracking at orders 4–6 with forward checking and symmetry breaking. "Not found" means abstention, never TRUE. A table must satisfy the hypothesis and break the goal at every/some assignment before WILL emits the judge's `Fin n`/`decideFin!` certificate.
- TRUE, matching chains: treats the hypothesis both directions, runs bidirectional BFS between the goal's sides, stores explicit rewrite positions/substitutions, re-walks the whole chain, then renders `calc`/`congrArg`.
- TRUE, completion: bounded Knuth–Bendix critical-pair completion; every lemma carries a replayable chain and is dropped if replay fails; sound projection/fresh-variable/variable-equality consequences can trigger an `ALLEQ` total-collapse proof.
- TRUE, given-clause (new): E-prover's core loop reimplemented in pure Python — derived equations processed lightest-first with an age-weight ratio, reaching the projection/collapse forcing lemmas blind saturation misses. This lets WILL prove left-projection laws (e.g. order-5 residual 0036) with no memorized proof; its body is an independently replayed chain of kernel-checkable steps.
- Solo adds up to six organizer-proxy LLM rounds from a single top-level PROMPT: proposed Lean is token-screened and judge-compiled, tables are exhaustively checked, a bridge lemma is used only if the chain engine proves both legs, and judge errors feed later rounds. Marathon disables the LLM (this build uses no HTTP proxy) and writes only self-verified proofs within a bounded per-problem slice.

## Embedded-data disclosure (required)
WILL embeds no implication matrix, lookup or answer bank, finite-model bank, per-law fact, or pair-specific certificate — nothing that names a problem or carries a verdict. It has exactly two payloads: the human-readable top-level `PROMPT` (reusable proof-search schemas + the JSON response contract), and `_GC_SRC_B64`, a zlib/base64 copy of the given-clause prover's SOURCE code. That blob is executable algorithm, not data: no equation, no table, no answer; it runs identically on any input. Compressing source rather than inlining it keeps the single file tidy; decompressing recovers ordinary Python. Runtime is Python stdlib only. Comparable behavior is reproduced by running the disclosed enumerators, backtracker, rewrite search, completion, and given-clause prover on new equations.

## Soundness and honest evidence
No LLM statement is trusted: FALSE tables pass two exhaustive evaluators; deterministic TRUE bodies come only from replayed derivations; Solo candidates must pass the official judge; `sorry`/`admit`/unsafe metaprogramming are screened. On a deterministic released benchmark (no LLM, no oracle) the pre-given-clause solver solved 50/50 FALSE and 34/50 TRUE; the given-clause tier is aimed exactly at the true-side misses and now carries the projection/collapse forcing laws it once abstained on, order-5 residuals 0030 and 0036 re-checked to compile on Lean 4.33.0 via AXLE. Released-set evidence only; the private set and the Solo LLM tier are unmeasured here.
